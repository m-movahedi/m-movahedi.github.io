Large Language Models (LLMs) can look mysterious from the outside: you type a prompt, the model writes back, and the response often feels more like conversation than computation. Under the hood, though, the core idea is surprisingly concrete. Most modern LLMs are built from **transformers**, trained to predict text one token at a time, and used during inference to repeatedly choose the next likely token.

This post is the first in a short series. We will start with transformers, then move into how LLMs learn, how they generate text, why training and inference are different, and what people mean when they talk about model parameters.

## 1. Text Becomes Tokens

LLMs do not read text as whole sentences. They first break text into **tokens**: common words, word pieces, punctuation marks, spaces, or byte-level fragments. A sentence like this:

<div class="llm-token-row" aria-label="Tokenized sentence example">
  <span class="llm-token">The</span>
  <span class="llm-token"> evac</span>
  <span class="llm-token">uation</span>
  <span class="llm-token"> plan</span>
  <span class="llm-token"> changed</span>
  <span class="llm-token">.</span>
</div>

might become a sequence of token IDs. Each ID is then mapped into an **embedding**, which is a vector of numbers. You can think of an embedding as the model's internal coordinate system for meaning, syntax, and usage.

The model also needs information about order. The same words can mean different things depending on position, so transformers add **positional information** to token embeddings before processing them.

```python
# Example: tokenizing with tiktoken (used by GPT-family models)
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4")
tokens = enc.encode("The evacuation plan changed.")
print(tokens)   # [976, 60038, 3197, 5614, 13]
print(len(tokens))  # 5 tokens from 4 words
```

    <li><a href="https://arxiv.org/abs/1808.06226">Kudo and Richardson (2018), "SentencePiece"</a>: important for understanding modern subword tokenization pipelines that work directly from raw text.</li>

## 2. Why Transformers Matter

Before transformers, many language models processed text mostly from left to right using recurrent neural networks. That worked, but it made long-range relationships difficult and slow to learn. Transformers changed the center of gravity by using **self-attention**.

Self-attention lets each token look at other tokens in the sequence and decide which ones matter for the current computation. For example, in "the bridge failed after it flooded," the model needs to connect "it" with the right earlier concept. Attention is one of the mechanisms that helps.

<div class="llm-note">
  <p><strong>Core intuition:</strong> a transformer does not simply store a sentence. It repeatedly rewrites every token's representation using context from nearby and distant tokens.</p>
</div>

### Attention: The Core Equation

<div class="llm-math">
  <p><strong>Deeper dive:</strong></p>
  <p><code>Attention(Q, K, V) = softmax(Q·Kᵀ / √dₖ) · V</code></p>
  <p>Q (queries) represent what each token is looking for. K (keys) represent what each token offers. V (values) represent the information each token carries. The dot product Q·Kᵀ measures how compatible each query is with each key — higher scores mean stronger relevance. Dividing by √dₖ (the square root of the key dimension) prevents these scores from growing too large, which would push softmax into regions with near-zero gradients. Softmax then turns the scaled scores into weights that sum to 1, so the output for each token is a weighted combination of all value vectors.</p>
</div>

### A Transformer Block

A transformer is built by stacking many similar blocks. Each block usually contains attention, a feed-forward network, normalization, and residual connections.

<div class="llm-code">
<pre>
Input Tokens
    ↓
[Token Embeddings + Positional Encoding]
    ↓
┌─────────────────────────────────┐
│   Multi-Head Self-Attention     │
│   + Residual Connection         │
│   + Layer Normalization         │
├─────────────────────────────────┤
│   Feed-Forward Network          │
│   + Residual Connection         │
│   + Layer Normalization         │
└─────────────────────────────────┘
    ↓  (repeat N times)
[Final Layer Norm]
    ↓
[Linear + Softmax → Token Probabilities]
</pre>
</div>

<div class="llm-flow" role="img" aria-label="Transformer block flow from tokens to output probabilities">
  <div class="llm-card">
    <strong>Tokens</strong>
    <p>Text becomes token IDs.</p>
  </div>
  <div class="llm-card">
    <strong>Embeddings</strong>
    <p>IDs become vectors with position information.</p>
  </div>
  <div class="llm-card">
    <strong>Self-Attention</strong>
    <p>Tokens exchange context with other tokens.</p>
  </div>
  <div class="llm-card">
    <strong>Feed-Forward</strong>
    <p>Each token representation is transformed.</p>
  </div>
  <div class="llm-card">
    <strong>Probabilities</strong>
    <p>The model scores possible next tokens.</p>
  </div>
</div>

The phrase **large language model** usually means a transformer with many layers, wide internal vectors, and a huge number of learned weights.

  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://arxiv.org/abs/1706.03762">Vaswani et al. (2017), "Attention Is All You Need"</a>: introduced the Transformer architecture and made attention the central operation.</li>
    <li><a href="https://arxiv.org/abs/1409.0473">Bahdanau, Cho, and Bengio (2014), "Neural Machine Translation by Jointly Learning to Align and Translate"</a>: an influential precursor that made neural attention central to sequence modeling.</li>

## 3. What an LLM Learns

The most common training objective is **next-token prediction**. During training, the model receives text and learns to predict the next token at many positions.

For a sentence like:

> During a hurricane, people may choose to evacuate because ___

the model learns to assign probabilities to possible continuations such as "roads," "officials," "risk," "family," or "flooding." It is not choosing from a fixed list of human-written answers. It is producing a probability distribution across its vocabulary.

<div class="llm-panel">
  <strong>Example next-token distribution</strong>
  <div class="llm-mini-chart" aria-label="Example token probabilities">
    <div class="llm-bar-row"><span>risk</span><div class="llm-bar"><span style="width: 42%;"></span></div><span>0.42</span></div>
    <div class="llm-bar-row"><span>officials</span><div class="llm-bar"><span style="width: 24%;"></span></div><span>0.24</span></div>
    <div class="llm-bar-row"><span>roads</span><div class="llm-bar"><span style="width: 17%;"></span></div><span>0.17</span></div>
    <div class="llm-bar-row"><span>family</span><div class="llm-bar"><span style="width: 10%;"></span></div><span>0.10</span></div>
    <div class="llm-bar-row"><span>coffee</span><div class="llm-bar"><span style="width: 2%;"></span></div><span>0.02</span></div>
  </div>
</div>

After seeing enormous amounts of text, the model learns patterns that support grammar, style imitation, translation, summarization, code generation, and some forms of reasoning. This is why next-token prediction is more powerful than it sounds. To predict language well, the model has to build internal representations of many things language refers to.

That said, an LLM is not a database in the ordinary sense. It stores knowledge in distributed patterns across weights, and it can be wrong, outdated, or overconfident.

<div class="llm-math">
  <p><strong>The training loss:</strong></p>
  <p><code>Loss = −Σ log P(correct token)</code></p>
  <p>This is cross-entropy loss. The loss is higher when the model assigns low probability to the actual next token — if the correct token gets probability 0.01, the log is a large negative number and the loss contribution is large. Training minimizes this loss across many examples, gradually pushing the model to assign higher probability to plausible continuations.</p>
</div>

<div class="llm-papers">
  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf">Radford et al. (2019), "Language Models are Unsupervised Multitask Learners"</a>: showed how large next-token models can display broad zero-shot behavior.</li>
    <li><a href="https://arxiv.org/abs/2005.14165">Brown et al. (2020), "Language Models are Few-Shot Learners"</a>: the GPT-3 paper, important for understanding scale, prompting, and few-shot use.</li>
  </ul>
</div>

## 4. Training Structure

During training, the model's parameters are still changing.

1. Text is collected and cleaned.
2. Text is tokenized into long sequences.
3. The model predicts the next token at many positions.
4. The predicted probabilities are compared with the actual next tokens.
5. The error becomes a loss value.
6. Backpropagation adjusts the parameters to reduce future error.

This process is repeated over massive batches of examples. The model gradually becomes better at assigning high probability to plausible continuations and lower probability to unlikely ones.

<div class="llm-two-col">
  <div class="llm-panel">
    <strong>Training</strong>
    <p>Weights are updated.</p>
    <p>The model sees many examples in parallel.</p>
    <p>The goal is to reduce prediction error.</p>
  </div>
  <div class="llm-panel">
    <strong>After Training</strong>
    <p>The learned weights are saved.</p>
    <p>The model can be deployed for use.</p>
    <p>No learning happens unless another training process is run.</p>
  </div>
</div>

Many deployed models also go through additional stages after pretraining, such as supervised fine-tuning, preference optimization, safety training, tool-use training, or domain adaptation. Those stages shape behavior, but the transformer foundation remains the same.

<div class="llm-papers">
  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://arxiv.org/abs/2001.08361">Kaplan et al. (2020), "Scaling Laws for Neural Language Models"</a>: explains how model size, data size, and compute relate to training loss.</li>
    <li><a href="https://arxiv.org/abs/2203.15556">Hoffmann et al. (2022), "Training Compute-Optimal Large Language Models"</a>: the Chinchilla paper, which shifted attention toward balancing parameters with enough training data.</li>
    <li><a href="https://arxiv.org/abs/2203.02155">Ouyang et al. (2022), "Training Language Models to Follow Instructions with Human Feedback"</a>: a key paper for instruction tuning and reinforcement learning from human feedback.</li>
  </ul>
</div>

## 5. Inference Structure

**Inference** is what happens when you use a trained model. The model receives a prompt and generates output one token at a time.

<div class="llm-flow" role="img" aria-label="Inference loop">
  <div class="llm-card">
    <strong>Prompt</strong>
    <p>User input and system instructions.</p>
  </div>
  <div class="llm-card">
    <strong>Forward Pass</strong>
    <p>The transformer computes next-token scores.</p>
  </div>
  <div class="llm-card">
    <strong>Select Token</strong>
    <p>A decoding method chooses one token.</p>
  </div>
  <div class="llm-card">
    <strong>Append</strong>
    <p>The selected token joins the context.</p>
  </div>
  <div class="llm-card">
    <strong>Repeat</strong>
    <p>The loop continues until stopping.</p>
  </div>
</div>

The important distinction is that inference does not normally update the model's parameters. The model may appear to learn within a conversation because previous messages remain in the context window, but that is temporary context use, not permanent weight updating.

<div class="llm-papers">
  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://arxiv.org/abs/2205.14135">Dao et al. (2022), "FlashAttention"</a>: important for understanding why efficient attention kernels matter for practical transformer inference.</li>
    <li><a href="https://arxiv.org/abs/2309.06180">Kwon et al. (2023), "Efficient Memory Management for Large Language Model Serving with PagedAttention"</a>: introduces vLLM/PagedAttention and explains the importance of KV-cache memory during serving.</li>
    <li><a href="https://arxiv.org/abs/2302.01318">Chen et al. (2023), "Accelerating Large Language Model Decoding with Speculative Sampling"</a>: a readable entry point for inference acceleration through draft-and-verify decoding.</li>
  </ul>
</div>

## 6. Generation and Decoding

At each generation step, the model outputs probabilities for possible next tokens. The decoding strategy controls how one token is selected.

- **Greedy decoding** chooses the highest-probability token every time. It is predictable but can be bland or get stuck.
- **Sampling** randomly draws from the probability distribution. It can be more varied, but also more error-prone.
- **Temperature** adjusts randomness. Lower temperature makes outputs more conservative; higher temperature makes outputs more exploratory.
- **Top-k sampling** restricts choices to the k most likely tokens.
- **Top-p sampling** restricts choices to the smallest set of tokens whose combined probability passes a threshold.
- **Beam search** tracks several candidate continuations at once. It is useful in some structured generation tasks, though less common for open-ended chat.

This is why the same prompt can produce different answers across runs. The model is not retrieving a single stored response. It is repeatedly constructing a continuation under a probability model and a decoding policy.

<div class="llm-papers">
  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://arxiv.org/abs/1904.09751">Holtzman et al. (2019), "The Curious Case of Neural Text Degeneration"</a>: introduced nucleus sampling and explains why high-probability decoding can produce repetitive text.</li>
    <li><a href="https://arxiv.org/abs/1805.04833">Fan, Lewis, and Dauphin (2018), "Hierarchical Neural Story Generation"</a>: an early influential use of top-k sampling for open-ended neural generation.</li>
  </ul>
</div>

## 7. Common LLM Architectures

Not every transformer-based language model is structured the same way. Three families matter most:

<div class="llm-two-col">
  <div class="llm-panel">
    <strong>Decoder-only models</strong>
    <p>Used by many chat and text-generation systems. They read previous tokens and predict the next token.</p>
    <p><em>Best fit:</em> open-ended generation, chat, code completion.</p>
  </div>
  <div class="llm-panel">
    <strong>Encoder-only models</strong>
    <p>Read the full input and produce contextual representations, but are not naturally designed to generate long text one token at a time.</p>
    <p><em>Best fit:</em> classification, search, embeddings, extraction.</p>
  </div>
  <div class="llm-panel">
    <strong>Encoder-decoder models</strong>
    <p>Use one transformer to understand the input and another to generate the output.</p>
    <p><em>Best fit:</em> translation, summarization, structured text-to-text tasks.</p>
  </div>
  <div class="llm-panel">
    <strong>Mixture-of-experts models</strong>
    <p>Route tokens through selected expert sub-networks instead of activating every parameter for every token.</p>
    <p><em>Best fit:</em> scaling capacity while controlling inference cost.</p>
  </div>
</div>

Most popular conversational LLMs are **decoder-only** because next-token generation maps naturally onto dialogue, writing, coding, and step-by-step responses.

<div class="llm-note">
  <p><strong>Beyond text:</strong> Modern LLMs increasingly handle images, audio, video, and structured data alongside text. These <em>multimodal</em> models use similar transformer foundations but add encoders or tokenizers for non-text inputs. The architectural principles from this post still apply; the input space is simply wider.</p>
</div>

<div class="llm-papers">
  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://arxiv.org/abs/1810.04805">Devlin et al. (2018), "BERT"</a>: the landmark encoder-only transformer for bidirectional representation learning.</li>
    <li><a href="https://arxiv.org/abs/1910.10683">Raffel et al. (2019), "Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer"</a>: the T5 paper, a major encoder-decoder reference.</li>
    <li><a href="https://arxiv.org/abs/2101.03961">Fedus, Zoph, and Shazeer (2021), "Switch Transformers"</a>: a key mixture-of-experts paper showing sparse scaling to very large parameter counts.</li>
  </ul>
</div>

## 8. Model Parameters

Model parameters are the learned numbers inside the network. They include embedding tables, attention projections, feed-forward layers, normalization terms, and output weights. When people say a model has 7 billion, 70 billion, or hundreds of billions of parameters, they are talking about the number of learned values used to transform input tokens into output probabilities.

<div class="llm-param-grid" role="img" aria-label="Types of parameters inside a transformer">
  <div class="llm-card">
    <strong>Embeddings</strong>
    <div class="llm-param-number">token to vector</div>
    <p>Store learned representations for vocabulary items.</p>
  </div>
  <div class="llm-card">
    <strong>Attention</strong>
    <div class="llm-param-number">Q K V</div>
    <p>Learn how tokens query, match, and exchange information.</p>
  </div>
  <div class="llm-card">
    <strong>Feed-Forward</strong>
    <div class="llm-param-number">transform</div>
    <p>Do much of the model's internal computation.</p>
  </div>
  <div class="llm-card">
    <strong>Output Head</strong>
    <div class="llm-param-number">scores</div>
    <p>Maps final vectors back to vocabulary probabilities.</p>
  </div>
</div>

More parameters can increase capacity, but parameter count is not the whole story. Data quality, architecture, training recipe, context length, tokenizer, alignment process, inference settings, and tool access all affect model behavior. A smaller well-trained model can outperform a larger poorly trained model on specific tasks.

There is also an important deployment distinction:

- **Total parameters**: all learned weights stored by the model.
- **Active parameters**: the subset used for a given token, especially relevant in mixture-of-experts models.
- **Context window**: the amount of text the model can consider at once. This is not the same as parameter count.

<div class="llm-papers">
  <strong>Important papers for this section</strong>
  <ul>
    <li><a href="https://arxiv.org/abs/2001.08361">Kaplan et al. (2020), "Scaling Laws for Neural Language Models"</a>: useful for the relationship between parameter count, data, compute, and loss.</li>
    <li><a href="https://arxiv.org/abs/2203.15556">Hoffmann et al. (2022), "Training Compute-Optimal Large Language Models"</a>: important because it shows that more parameters alone are not enough; training tokens matter too.</li>
    <li><a href="https://arxiv.org/abs/2006.16668">Lepikhin et al. (2020), "GShard"</a>: an important sparse/mixture-of-experts scaling paper for distinguishing total parameters from active computation.</li>
  </ul>
</div>

## 9. A Compact Mental Model

If you remember only one thing, use this:

<div class="llm-note">
  <p>An LLM is a large transformer trained to predict the next token. At inference time, it turns your prompt into vectors, computes next-token probabilities, selects a token, appends it to the prompt, and repeats.</p>
</div>

That loop is simple. The scale is not. The power of LLMs comes from running this simple prediction game across huge datasets, with billions of learned parameters, and then using the trained model inside carefully designed inference systems.
